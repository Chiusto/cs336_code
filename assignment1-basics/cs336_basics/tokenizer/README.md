### 尝试 BPE 分词器训练

让我们在 TinyStories 数据集上训练一个字节级 BPE 分词器。查找/下载数据集的说明见第 1 节。开始之前，我们建议先浏览一下 TinyStories 数据集，了解数据内容。

**并行化预分词**

你会发现主要瓶颈是**预分词**步骤。你可以使用内置库 `multiprocessing` 并行化代码来加速预分词。具体而言，我们建议在并行预分词实现中，将语料库**分块**，同时确保块边界出现在特殊词元的开头。你可以直接照搬以下链接中的起始代码来获取块边界，然后将其用于在进程间分配工作：

```
https://github.com/stanford-cs336/assignment1-basics/blob/main/cs336_basics/pretokenization_example.py
```

这种分块总是有效的，因为我们从不想跨越文档边界进行合并。就本作业而言，你总是可以这样切分。不用担心"收到一个不包含 `<|endoftext|>` 的极大语料库"这种边缘情况。

**预分词前移除特殊词元**

在使用正则模式（`re.finditer`）运行预分词之前，你应该从语料库（或并行实现中的块）中**剥离所有特殊词元**。确保你在特殊词元处切分，这样就不会跨越它们分隔的文本进行合并。例如，如果你的语料库（或块）形如 `[Doc 1]<|endoftext|>[Doc 2]`，你应该按特殊词元 `<|endoftext|>` 切分，并分别对 `[Doc 1]` 和 `[Doc 2]` 预分词，这样就不会跨越文档边界进行合并。换言之，特殊词元在训练期间定义了**硬性分割边界**，但它们本身不应计入合并统计。这可以通过 `re.split` 实现，以 `"|".join(special_tokens)` 作为分隔符（注意小心使用 `re.escape`，因为 `|` 可能出现在特殊词元中）。测试 `test_train_bpe_special_tokens` 会检验这一点。

**优化合并步骤**

上面风格化示例中 BPE 训练的**朴素实现**很慢，因为每次合并都要遍历所有字节对来找出频率最高的对。然而，每次合并后发生变化的只有与合并对**重叠**的那些对的计数。因此，可以通过索引所有对的计数并**增量更新**这些计数来提高 BPE 训练速度，而不是显式遍历每一对字节来统计对频率。使用这种缓存过程可以获得显著的加速，不过我们注意到，BPE 训练的合并部分在 Python 中无法并行化。

> **🪶 低资源提示：性能分析**
>
> 你应该使用 `cProfile` 或 `py-spy` 等性能分析工具找出实现中的瓶颈，并集中精力优化它们。

> **🪶 低资源提示："缩小规模"**
>
> 与其直接跳到在完整 TinyStories 数据集上训练分词器，我们建议先在一个小的数据子集（"调试数据集"）上训练。例如，你可以在 TinyStories 验证集上训练分词器，它只有 22K 个文档而不是 2.12M 个。
>
> 这体现了一个通用策略：只要有可能就缩小规模以加速开发，例如使用更小的数据集、更小的模型等。选择调试数据集或超参数配置的规模需要仔细考虑：你希望调试集足够大，以便与完整配置有相同的瓶颈（这样你的优化才能推广），但又不能大到运行起来没完没了。

**题目 (train_bpe)：BPE 分词器训练（15 分）**

提交内容：编写一个函数，给定输入文本文件的路径，训练一个（字节级）BPE 分词器。你的 BPE 训练函数应（至少）处理以下输入参数：

- `input_path: str` — 包含 BPE 分词器训练数据的文本文件路径。
- `vocab_size: int` — 定义最终词表最大大小的正整数（包括初始字节词表、合并产生的词表项以及任何特殊词元）。
- `special_tokens: list[str]` — 要加入词表的字符串列表。训练期间将其视为硬性边界，防止跨其范围进行合并，但计算合并统计时不要包含它们。

你的 BPE 训练函数应返回最终的词表和合并：

- `vocab: dict[int, bytes]` — 分词器词表，从 `int`（词表中的词元 ID）到 `bytes`（词元字节）的映射。
- `merges: list[tuple[bytes, bytes]]` — 训练产生的 BPE 合并列表。每个列表项是一个字节元组 `(<token1>, <token2>)`，表示 `<token1>` 与 `<token2>` 合并。合并应按创建顺序排列。

要根据我们提供的测试测试你的 BPE 训练函数，你首先需要实现 `[adapters.run_train_bpe]` 处的测试适配器。然后运行 `uv run pytest tests/test_train_bpe.py`。你的实现应能通过所有测试。（可选，可能需要大量时间投入）你可以用某种系统语言实现训练方法的关键部分，例如 C++（考虑 `cppyy` 或 `nanobind`）或 Rust（使用 PyO3）。如果这样做，请注意哪些操作需要复制、哪些可以直接从 Python 内存读取，并务必留下构建说明，或确保它仅使用 `pyproject.toml` 即可构建。另请注意，GPT-2 正则表达式在大多数正则引擎中支持不佳，在支持它的引擎中大多也太慢。我们已经验证 Oniguruma 相当快且支持负向前瞻，但 Python 的 `regex` 包如果不更快的话也至少同样快。
